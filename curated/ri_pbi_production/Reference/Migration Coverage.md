# Migration Coverage

The ledger of what happened to every Markdown document in the `ri_pbi_production` workspace when its content moved into this vault. One row per source doc, **48 rows, no exceptions** — a doc with no row is a doc nobody decided about.

`source_docs: []` above is deliberate and not an oversight: this note absorbs nothing. It is *about* absorption.

## How to read it, and what is trustworthy

Only the **Status** column is hand-assigned. The **Absorbed by** column is *derived* — it lists the vault notes whose `source_docs` frontmatter names that path, read straight from the notes at generation time. Nobody types it, so it cannot quietly disagree with what the notes actually claim.

`tools/vault-lint/check-ledger.js` reconciles the whole table **in both directions** on every run:

| It fails when | Which means |
|---|---|
| a workspace `.md` has no row | a doc was missed entirely — the failure this ledger exists to catch |
| a row names a file not on disk | the doc moved or was deleted and the ledger wasn't told |
| a note's `source_docs` names a path with no row | usually a typo in a frontmatter path |
| a row says `absorbed` but no note claims it | the note that absorbed it forgot to declare it |
| a row's status is not one of the four below | a typo, or an invented status |

Run it as `node tools/vault-lint/check-ledger.js <vault> <workspace>`. It exits non-zero on any of the above, which is what makes "every source doc is accounted for" a checkable statement rather than a claim.

## The four statuses

| Status | Count | Meaning |
|---|---|---|
| `stubbed` | 22 | The vault is now the place to read this. The file stays in the repo but is reduced to a short pointer plus whatever a person needs *at the terminal, in that repo*. |
| `indexed` | 15 | Stays authoritative in the repo. The vault points at it and quotes figures from it, but never takes it over. |
| `absorbed` | 11 | Content re-synthesised into vault notes. The original stays as a dated historical record; nothing further is planned for it. |
| `superseded` | 0 | Defined but currently unused — no source doc has been retired outright. |

The distinction that matters most is **`indexed` versus `stubbed`**, because it is the one that can cause damage if confused. Two groups are `indexed` for concrete, mechanical reasons:

- **`docs/rls-role-naming/**` (11 files)** — rendered output of `New-HandoverDocs.ps1`, generated from CSVs that come from a live Databricks pull. Hand-edit any of it and the next pipeline run overwrites the edit. See [[RLS Role Naming Normalization]].
- **`PBI_Manual_QA_Test_Plan.md`** — the declared source of truth for `PBI_Manual_QA_Test_Plan.xlsx`, regenerated by parsing its Markdown tables keyed on check ID. It has to keep its exact table shape and its position beside the workbook. See [[QA Test Plan]].

`tools/delivery-matrix/README.md` is `indexed` for a softer reason: [[Delivery Matrix]] explicitly defers to it for rebuild mechanics rather than duplicating them.

The two `2026-09-01-obsidian-migration` documents are the spec and plan governing *this* migration. They are `indexed` and show no absorbing note, which is correct — nothing absorbs them, and they are the record of why every other row says what it says.

## Why 48 rows and not 47

The implementation plan predicted 47. The extra row is `docs/superpowers/plans/2026-09-01-obsidian-migration.md` — the plan file itself, which did not exist at the moment its own document count was written. The count was right when made; the act of saving the plan changed it.

Nine files under `tools/vault-lint/fixtures/` are **excluded by design** and have no rows. They are deliberately malformed notes used to test the linters, not workspace documentation; the reconciler skips that directory explicitly.
